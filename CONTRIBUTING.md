# Contributing

Use Linux x86-64 for the reference fixtures, Node from [`.node-version`](.node-version), Python 3.11+, GNU binutils (`as`, `ld`), `curl`, and `sha256sum`. The packaged Chromium headless shell needs standard Chromium runtime libraries, including NSS and NSPR (`libnss3` and `libnspr4` on Debian/Ubuntu). `CHROMIUM_PATH` can point to a system Chromium binary instead. The first browser run downloads a checksum-verified SeaBIOS fixture from GitHub.

```sh
npm ci
npm test
npm run test:browser
npm run bench
```

If using the pinned shell on a minimal Linux image without NSS/NSPR, install the system packages or unpack the shell's matching runtime libraries locally:

```sh
mkdir -p browser-results/chromium-libs
node -e 'require("fs").createReadStream("node_modules/@sparticuz/chromium/bin/al2023.tar.br").pipe(require("zlib").createBrotliDecompress()).pipe(process.stdout)' \
  | tar -xf - -C browser-results/chromium-libs
export LD_LIBRARY_PATH="$PWD/browser-results/chromium-libs/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
```

## Workspace layout

- `core/`: ISA, Wasm code generation and atomic instruction probes. The Phase 0 emitters are JS so the same generated bytes can be tested in Node and Chromium; the production core remains Rust → Wasm per the roadmap.
- `host/`: worker orchestration and storage/display/terminal/network probes. This is throwaway ESM/JS host code, not a change to the roadmap's TypeScript choice.
- `relay/`: local test relay only. Do not deploy it or expose it off loopback.
- `web/`: browser test fixtures and development-only IWA. This is not the user-facing PWA.
- `guest/` and `image/`: reserved for guest-side tools and image construction; this PR does not ship a guest image.
- `benchmarks/`, `docs/`, and `scripts/tests/`: fixtures, results, ADRs, and regression tests.

Keep hot paths off the main thread and case-specific fixtures isolated from production code. Add a deterministic correctness test for functional fixes; benchmark numbers on shared CI runners are observational, not timing assertions. When reporting performance, include the full source SHA, workload and fixture version, host/browser and adapter, sample distribution, and what the proxy cannot establish. Do not commit generated guest/rootfs images, dependency directories, or large results. See [ADR-0011](docs/adr/0011-license.md) before adding dependencies or redistributing third-party artifacts.
